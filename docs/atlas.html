先分层，
再比较 Harness。

AI Harness Atlas 是一份独立观察图谱：记录多类 Harness 的架构边界、版本变化和公开讨论。它不是任何项目的官方文档，也不替项目方做质量排名。

独立观察 · 非官方多对象 · 多版本公开资料优先未知项保留未知

为什么要先分层？ “Harness”在不同项目里可能指运行时、SDK、编排框架或完整 Coding Agent。把它们放在同一张榜单，会让读者误以为它们在解决同一个问题。本图谱先标出对象所在的运行层，再沿同一组问题阅读差异。

读者先带走三句话

01

模型不是 Harness

模型负责生成判断；Harness 负责把判断接到上下文、工具、权限、状态和真实环境。

02

对象不在同一层

SDK、编排运行时、Harness runtime 和 Coding Agent 产品可以互相组合，但职责并不相同。

03

版本决定结论

每个对象的版本档案独立保存；公开讨论没有写版本时，只归入时间观察窗口，不强行推断补丁号。

对象类型

HARNESS RUNTIME

把 Agent 运行起来

关注循环、服务、状态、工具和生命周期如何组成可替换的运行时。

DSH · Pi Agent Runtime
AGENT SDK

把构件交给开发者

提供 Agent、Runner、工具、交接、护栏、会话或工作区等可组合接口。

OpenAI Agents SDK · OpenHands SDK
ORCHESTRATION

把长任务和状态接住

处理持久执行、检查点、暂停恢复、人机协同和多 Agent 状态图。

LangGraph · Deep Agents
CODING AGENT

把能力做成产品

将运行时、工具、权限、工作区和界面组合成可直接使用的编码代理。

Pi · Codex CLI · Gemini CLI · Cline · Claude Code · OpenCode

共同观察维度

问题读者要理解什么不应该误读成什么
运行循环一次请求如何进入模型、工具和下一步模型本身的能力排名
上下文与记忆哪些内容会保留、压缩、交接或丢失“上下文越大就一定越好”
工具与扩展工具如何注册、发现、验证与替换插件数量等于产品能力
权限与恢复什么动作需要批准、如何暂停、回滚和继续有确认弹窗就代表安全
编排与交接子 Agent、工作区和长任务如何传递状态多 Agent 数量越多越先进
观测与验证能否看到轨迹、错误、来源和验证结果日志越多就越可靠

版本与公开讨论

版本档案回答“这个对象在什么时候是什么状态”；公开讨论观察回答“当时公开社区正在谈什么”。两者不互相冒充。

  1. 明确版本：原始资料写出 release、tag 或 commit 时，绑定到该版本。
  2. 观察窗口：帖子没有精确版本号时，保留原帖日期与本站记录日期，归入相应时间窗口。
  3. 证据边界：官方资料、社区原文和本站解释分栏展示；缺少资料时显示“未说明”。
  4. 独立立场：本站不代表任何项目方，也不提供官方支持、漏洞报告或产品承诺。
