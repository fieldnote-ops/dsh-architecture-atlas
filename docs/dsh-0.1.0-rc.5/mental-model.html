核心心智模型

把 DSH 想成一张随配置和服务变化而重排的能力图，会比“核心程序加载一串插件”更接近真实运行方式。

DSH v0.1.0-rc.5五层架构Everything is a plugin
最短版本

Profile 说明想要什么；Loader 让运行态向目标靠拢；Context 保存当前可用的服务；Fiber 管理每个插件的生命周期；领域插件共同组成 Agent。

Agent 是一张服务拓扑

在 DSH 中，Agent 不是一个永远存在的主对象。当前 Context 中同时可用的会话、提示词、工具、Agent Loop 和 LLM 服务，构成了此刻的 Agent。替换其中一项，依赖图会重新协调。

这解释了官方所说的 Everything is a Plugin：Loop 也没有特权，它和工具或模型适配器一样，通过服务契约进入系统。

记住三条方向

↓配置向下

Profile 描述目标，Loader 把差异交给生命周期协调。

↑可用性向上

服务出现或消失，决定依赖者激活、等待还是退出。

↺恢复向内

插件产生的 effect 归属自己的 Fiber，卸载时逆序撤销。

五个层次各管什么

  1. 声明与配置：用 Profile、Bundle 和 Patch 组合目标系统。
  2. 运行时协调：Loader 比较当前状态和目标状态，安排必要更新。
  3. 统一上下文：Context 解析服务、隔离范围、事件和效应。
  4. 插件生命周期：Fiber 表达等待、激活、失败与卸载。
  5. Agent 能力：Session、Tools、Agent Loop 和 LLM 完成领域工作。

它们不是传统意义的五层调用栈。一次服务变化可能从 Context 向上影响领域插件，又由 Fiber 向内触发清理。

用更换 LLM 举例

用户 Patch 指向新的模型适配器。Loader 发现目标发生变化，准备候选插件。候选通过 Context 提供新的 ctx.llm；依赖该服务的 Agent Loop 被 Fiber 重新协调。旧适配器退出时，它建立的连接和监听器按 effect 记录撤销。

这里没有一段“先停 Loop、再换 LLM、最后重启 Loop”的固定脚本。顺序来自服务依赖，恢复来自生命周期记录。
