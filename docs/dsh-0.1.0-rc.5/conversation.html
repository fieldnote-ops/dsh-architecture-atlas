一次对话如何运行

下面从一条用户消息出发，追踪它如何进入会话、调用模型和工具，再变成下一轮可见的上下文。

DSH v0.1.0-rc.5SessionTurn / Step
运行前提

ctx.sessions、ctx.systemPrompt、ctx.tools、ctx.agents、ctx.agentLoop 和 ctx.llm 已在当前 Context 中可用。

1. 用户输入进入 Session

消息先写入追加式会话记录。Session 是后续步骤的事实来源：界面显示、模型上下文和工具结果都应能沿记录重建，而不是依靠某个页面组件的临时状态。

2. Loop 组装当前 Step

Agent Loop 读取会话记录、系统提示片段和当前可用工具。它还会取得 Agent 与 LLM 服务，形成这一步的模型请求。工具 schema 在这里与普通提示词一起进入模型上下文。

Turn 是一次用户回合；Step 是其中的一次模型判断。发生工具调用时，一个 Turn 可以包含多个 Step。

3. LLM 返回文本或工具意图

LLM 适配器处理供应商请求和流式事件。模型可能直接返回文本，也可能请求调用一个或多个工具。适配器负责跨模型差异，Loop 只依赖稳定的服务接口。

4. 工具管线执行调用

Tools 服务根据名称找到执行器，校验参数，并在当前 Scope 中运行。权限、沙箱或环境限制可以在工具执行链上介入。执行结果随后写回 Session，成为下一次 Step 的输入。

5. 回合结束或继续

如果模型还需要处理工具结果，Loop 开始下一个 Step；如果已经得到面向用户的结果，这个 Turn 结束。流式内容和事件会同步给订阅者，但完整的会话事实仍以 Session 记录为准。

RECORD记录输入

用户消息追加到会话。

DECIDE模型判断

Loop 组织上下文并调用 LLM。

ACT / REPEAT执行或结束

工具结果回写，必要时进入下一 Step。

排查问题时看哪里

  • 模型没有看到某条信息：先检查 Session 记录与 Prompt 组合。
  • 工具没有出现：检查 ctx.tools 当前范围和 schema 生成。
  • 工具执行后没有继续：检查结果是否写回 Session，以及 Loop 是否开始下一 Step。
  • 更换模型后行为异常：区分 LLM 适配问题和 Loop 决策问题。
