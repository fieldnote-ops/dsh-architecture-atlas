领域插件把前四层的运行时机制变成 Agent 能力。会话、提示词、工具、循环和模型都以服务进入 Context，没有哪一个天然拥有“核心”地位。

DSH v0.1.0-rc.5commit 47f9438领域插件
一句话模型

一个正在运行的 DSH Agent，可以看成 ctx.sessions、ctx.systemPrompt、ctx.tools、ctx.agents、ctx.agentLoop 与 ctx.llm 在当前范围内同时可用。

它解决什么问题

传统 Agent 框架常把循环、模型调用和工具执行焊在一个主类里，周边能力才叫插件。DSH 把这条边界再往里推：默认 Agent Loop 也只是服务提供者，LLM 是适配接缝，工具系统和会话系统各自维护领域语义。

这样一来，“替换 Agent 行为”不必 fork 整个应用。只要新插件满足相同服务契约，并在 Context 中进入适当范围，依赖它的上层就可以按生命周期规则重新协调。

Everything is a plugin 的工程含义：不是所有文件都叫 plugin，而是运行所需的领域能力都通过同一套服务、依赖和生命周期机制进入系统。

六个主要服务接缝

Context 键领域职责阅读时关注
ctx.sessions追加式会话事件日志模型可见上下文如何从记录重建
ctx.systemPrompt提示词片段与工具 schema多个来源如何组合系统提示
ctx.tools工具注册表与执行管线发现、校验、调用与结果回写
ctx.agentsAgent 接口与活跃注册表不同 Agent 实现怎样被发现
ctx.agentLoopTurn / Step 默认驱动何时调用模型，何时执行工具
ctx.llm模型适配器接缝供应商差异如何停在边界内

scope 不只是表中的另一个业务服务。它把运行范围带入这些领域能力，帮助同一套服务在不同会话、Agent 或隔离上下文中解析出合适的行为。

一次对话如何穿过领域层

01 / RECORD输入进入 Session

用户消息先成为会话事实，后续模型上下文可以从事件日志重建。

02 / DECIDELoop 组织一次 Step

读取 prompt、tools、agent 与 llm，组装请求并判断下一步。

03 / ACT模型或工具返回

流式输出、工具调用与结果继续写回会话，推动下一次 Step。

Session 是事实来源，不只是聊天数组

会话采用追加式事件记录。消息、模型输出和工具结果沿事件顺序进入日志，“模型看见了什么”应当可以从记录重建。这为追踪、恢复和界面同步提供共同事实来源。

Prompt 和 Tools 都是可组合输入

系统提示不是散落在 Loop 内的一长段字符串；工具也不是模型调用函数里的硬编码表。它们各自由服务管理，Loop 在运行时读取当前范围内可用的片段、schema 与执行器。

Agent Loop 本身也能替换

默认 Loop 用 Turn / Step 推进一次对话，但它通过 ctx.agentLoop 提供能力，而不是框架不可替换的主循环。实验新的规划方式、审批策略或多步执行时，可以把变化限制在这一接缝。

关键规则

  • 服务契约比具体类更重要。领域插件通过 Context 键协作，不应依赖另一实现的内部状态。
  • Session 保留可重建事实。瞬时 UI 状态不应冒充会话历史。
  • Prompt 与 Tools 在运行时组合。不同插件可以在自己的范围内贡献片段和工具。
  • LLM 停在适配边界。模型供应商差异不应渗入所有领域插件。
  • Loop 没有特权。它依赖别的服务，也会随依赖消失而被 Fiber 协调。
  • 流式控制是重要工程扩展。事件、并发工具和 token 流超出简化形式模型时，应回到实现逐项核对。

常见误解

误解

插件只是给一个稳定 Agent 核心增加额外工具或界面。

更准确的理解

在 DSH 中，会话、模型、工具、Agent 和 Loop 本身都由插件提供；这些服务拓扑就是正在运行的 Agent。

误解

换一个模型只需要把 URL 和 API Key 改掉。

更准确的理解

适配器还要处理请求形态、流式事件、工具调用与错误语义；边界稳定不代表实现差异消失。
