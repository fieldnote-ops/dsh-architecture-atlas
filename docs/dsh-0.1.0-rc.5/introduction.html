DSH 是什么

DeepSeek Harness 是一个开源 Agent Harness。模型负责决定下一步，DSH 负责把这一步放进真实的会话、工具和运行环境中。

DSH v0.1.0-rc.5Developer PreviewMIT
先记住这一点

DSH 不是一个固定的 Agent 核心。会话、提示词、工具、模型连接和 Agent Loop 都是插件提供的服务，Cordis 负责让它们在依赖满足时运行。

Harness 负责什么

大模型只产生文本或结构化意图。要让 Agent 真正工作，还需要保存对话、组织系统提示、列出可用工具、执行工具调用、处理流式输出，并把结果写回会话。Harness 把这些工作连成一条可观察的运行链。

DSH 还要处理运行时变化。插件可能晚于应用启动才出现，依赖也可能暂时失效；配置更新不能把系统留在新旧混合的状态。这部分由 Cordis 的 Context 和 Fiber 机制承担。

系统由什么组成

CONFIGURATION声明系统

Profile、Bundle 与 Patch 描述这次运行需要哪些能力。

RUNTIMECordis 运行时

Loader、Context 和 Fiber 处理服务发现、依赖与生命周期。

DOMAINAgent 能力

Session、Prompt、Tools、Agent Loop 与 LLM 完成一次对话。

这三个部分不是三段固定调用。配置向运行时声明目标；服务可用性反过来决定插件能否激活；卸载时，Fiber 沿依赖关系和 effect 记录恢复旧状态。

当前项目状态

DSH 官方仓库将项目标记为 Developer Preview。接口和配置仍可能变化，因此本站按 DSH 版本保存文档。当前内容对应 v0.1.0-rc.5、提交 47f9438 和 vendored Cordis 4.0.1。

需要在项目中采用 DSH 时，请同时查看对应版本的官方 README 和架构文档，不要把本文描述直接套到其他版本。
