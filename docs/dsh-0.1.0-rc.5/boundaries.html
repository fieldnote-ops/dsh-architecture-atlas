能力边界与版本

这一页专门区分“运行时可以保证什么”和“仍要由插件或具体版本负责什么”。

DSH v0.1.0-rc.5commit 47f9438核对日期 2026-08-14

运行时提供的保证

  • 服务依赖未满足时，插件可以停在 PENDING，而不是读取不存在的服务。
  • 插件产生的 effect 归属当前 Fiber，并在卸载时按 LIFO 调用 disposer。
  • 提供者退出前，依赖它的插件会先收到服务不可用并开始排空。
  • Loader 可以等待相关生命周期沉淀，再决定提交候选或恢复旧状态。

插件仍要负责的部分

disposer 是否真的撤销了外部副作用，框架无法替插件证明。直接 import 内部对象、写全局变量或漏掉清理函数，也会绕开依赖和 effect 机制。

需要跨重载保留的状态必须放在替换边界之外。否则旧 runner 退出时，组件内存会一起消失。

形式模型没有覆盖全部工程行为

Cordis 论文解释统一上下文、可逆效应和生命周期转移。DSH 还使用 waterfall、parallel、serial 事件、异步工具调用和 LLM 流式输出。这些是必要工程能力，但没有被简化演算逐项描述。
